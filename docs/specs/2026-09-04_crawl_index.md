# Spec: PDS4 JIRAM label crawler and frame index (milestone 1)

Working directory: /expanse/lustre/projects/cla119/kaushiks/jiram_catalog
(a `uv` project, Python 3.12, src layout; package `jiram_catalog` in
`src/jiram_catalog/`). Network access to https://atmos.nmsu.edu works with
the system CA bundle. `wget` 1.19 is on PATH.

## Goal
A CLI `jiram-catalog` with four subcommands (`manifest`, `mirror`,
`index`, `stats`) that (1) enumerates the Juno JIRAM PDS4 calibrated
archive, (2) mirrors labels and camera image files to a local directory,
(3) parses every mirrored camera label into one Parquet table of frames
with sequence segmentation, and (4) prints summary statistics.

## Archive facts (measured 2026-09-04)
- Base URL `https://atmos.nmsu.edu/PDS/data/PDS4/juno_jiram_bundle/data_calibrated/`.
  Contains `orbit01` … `orbit77` (72 directories; some numbers are
  missing, e.g. orbit59/60/69/71/74), plus `collection_data_calibrated.xml`
  and `collection_data_calibrated_inventory.csv`.
- Listings are Apache mod_autoindex HTML. Entries look like
  `<a href="JIR_IMG_RDR_2017033T114006_V02.IMG">…</a>  2017-12-14 10:17  216K`.
  Sizes are rounded (K/M suffix); treat them as approximate. Ignore `href`
  values starting with `?` or `/` and the parent-directory link.
- File name pattern: `JIR_[LOG_]<IMG|SPE>_RDR_<YYYYDDDTHHMMSS>_V<NN>.<ext>`.
  Families by prefix: `JIR_IMG_RDR_` -> `IMG` (extensions `.IMG .LBL .xml`),
  `JIR_SPE_RDR_` -> `SPE` (`.DAT .LBL .xml`), `JIR_LOG_IMG_RDR_` -> `LOG_IMG`
  (`.TAB .LBL .xml`), `JIR_LOG_SPE_RDR_` -> `LOG_SPE` (`.TAB .LBL .xml`).
  Anything else -> `OTHER`. `product_id` = basename without extension.
- orbit04 holds 1111 IMG products (15,330 files total). Archive-wide there
  are 85,108 IMG products. IMG files are 128 lines x 432 samples float32
  big-endian (221,184 bytes). Total IMG bytes archive-wide ~21 GB.
- Kinds: `labels` = `.LBL` and `.xml`; `data` = `.IMG`/`.DAT`/`.TAB`.
- The `.LBL` (PDS3 syntax) carries everything the index needs; a sample is
  at `docs/samples/JIR_IMG_RDR_2017033T114006_V02.LBL` (read it). It uses
  `KEY = VALUE` with units in `<…>`, quoted multi-line strings, a
  `QUATERNION = (…)` sequence, a `SPICE_FILE_NAME = {…}` set, a namespaced
  key `JNO:TARGET_PRESENCE_FLAG`, `GROUP = L_BAND_PARAMETERS` /
  `M_BAND_PARAMETERS`, `OBJECT = FILE` containing `OBJECT = IMAGE` and
  `OBJECT = HISTORY`, a pointer `^IMAGE = "…"`, and the string `"N/A"` for
  unavailable numeric values. Parse it with `pvl.load`; if `pvl` raises,
  retry with `pvl.load(path, grammar=pvl.grammar.OmniGrammar())`; if that
  also raises, the row is still emitted with `parse_ok=False`,
  `parse_error=<exception text>`, `product_id` from the file name and all
  other columns null. Never let one bad label abort the index.
- Robots: only the `Wget` user agent is allowed under `/PDS/`. Use wget for
  all file downloads with its default user agent; use at most `--jobs`
  concurrent wget processes (default 3, hard cap 4), one process per orbit.

## Mirror root and layout
Mirror root: `--mirror PATH`, else env `JIRAM_MIRROR`, else
`/expanse/lustre/projects/cla119/kaushiks/jiram_mirror`. Layout:
```
<mirror>/pds4/juno_jiram_bundle/data_calibrated/orbitNN/<files as in archive>
<mirror>/manifest/listing_orbitNN.html      raw listing cache
<mirror>/manifest/manifest.parquet          one row per archive file
<mirror>/index/frames.parquet               one row per IMG label
<mirror>/index/stats.md                     output of `stats`
<mirror>/logs/wget_orbitNN_<YYYYmmddTHHMMSS>.log
```
The inventory CSV already present under `<mirror>/pds4/...` must be left
in place.

## Subcommands
Common options: `--mirror`, `--orbits SPEC` where SPEC is `all` or a
comma list of integers and ranges (`4`, `4,5,10-20`); default `all`.

1. `manifest [--refresh]`: fetch the `data_calibrated/` listing, then each
   selected orbit's listing (cached as `listing_orbitNN.html`; re-fetched
   only with `--refresh` or when the cache file is missing). Write
   `manifest.parquet` with columns: `orbit:int16` (from the directory name),
   `basename:str`, `ext:str` (without dot, as listed, case preserved),
   `family:str`, `kind:str` (`labels`/`data`/`other`), `product_id:str`,
   `url:str`, `listed_size_bytes:int64` (approximate, -1 if absent),
   `listed_mtime:str`. Rows for orbits not selected are kept from an
   existing manifest; selected orbits are replaced. Print a per-orbit
   count table (orbit, IMG products, SPE products, files).
2. `mirror [--family img|spe|log|all] [--kinds labels,data] [--jobs N] [--verify]`:
   defaults `--family img`, `--kinds labels,data`, `--jobs 3`. Builds the
   manifest first if missing for the selected orbits. For each selected
   orbit, in this order: (a) labels, (b) data. A file is skipped when it
   already exists and is complete: for `.LBL` the last non-blank line is
   `END`; for `.xml` the file ends with `</Product_Observational>`; for
   data files the size equals the label-declared size
   (`FILE_RECORDS * RECORD_BYTES` from the sibling `.LBL`, which is always
   downloaded first) or, when no `.LBL` is present, size > 0. Incomplete
   files are deleted and re-downloaded. Downloads: write the missing URLs
   for the orbit to a temp list file and run
   `wget -q -nd -P <orbit dir> --tries=3 --timeout=60 --waitretry=5 -o <log> -i <list>`
   (one wget per orbit, up to `--jobs` orbits concurrently via
   `concurrent.futures.ThreadPoolExecutor`). After wget returns, re-check
   completeness and report per-orbit counts: requested, downloaded,
   skipped, failed (with the first 10 failed basenames). Exit status 1 if
   any file failed. `--verify` additionally computes the MD5 of every data
   file and compares it with `MD5_CHECKSUM` in the sibling `.LBL`;
   mismatches are re-downloaded once and re-checked; remaining mismatches
   are reported and cause exit status 1.
3. `index [--jobs N]`: parse every `JIR_IMG_RDR_*.LBL` under the selected
   orbit directories (multiprocessing pool, default `--jobs` = min(8, cpu
   count)) into `frames.parquet` (schema below). Rows for orbits not
   selected are kept from an existing `frames.parquet`; selected orbits are
   replaced. After the table is built, compute the sequence columns over
   the whole table. Print: rows, rows with `parse_ok=False`, per-orbit
   counts by band, number of sequences.
4. `stats`: read `frames.parquet` (selected orbits) and print, also writing
   the same text to `<mirror>/index/stats.md`: total frames; frames by
   band; per-orbit table (orbit, frames, L, M, sequences, first start_time,
   last start_time, IMG bytes = sum of `img_size_bytes`); histogram of
   sequence length `seq_n` (bins 1,2,3-5,6-10,11-20,21-50,51+); histogram
   of `seq_gap_s` (bins <25, 25-35, 35-45 s); count of sequences whose
   `seq_n` differs from the archive's `sequence_samples` of their first
   frame; count of frames with `center_lat` null; fraction of frames with
   `abs(center_lat) >= 60`.

## `frames.parquet` schema (exact column names; dtypes as noted)
Identity: `product_id:str`, `orbit:int16` (ORBIT_NUMBER), `orbit_dir:int16`
(from the directory name), `version:str` (e.g. `V02`), `family:str`
(`IMG`), `band:str`, `geom_band:str`, `label_path:str` (relative to mirror
root), `img_file_name:str` (`^IMAGE` pointer), `img_size_bytes:int64`
(`FILE_RECORDS*RECORD_BYTES`), `img_present:bool` (data file exists with
that size at index time), `md5_checksum:str`, `parse_ok:bool`,
`parse_error:str` (empty when ok).
Time: `start_time`, `stop_time` (`datetime64[ns]`, naive UTC, from
START_TIME/STOP_TIME), `exposure_s:float64` (= stop - start in seconds),
`sclk_start:str`, `sclk_stop:str`.
Archive bookkeeping: `sequence_number:int16` (SEQUENCE_NUMBER),
`sequence_samples:int16` (SEQUENCE_SAMPLES), `command_file_name:str`,
`mission_phase_name:str`, `instrument_mode_id:str`,
`instrument_mode_desc:str` (whitespace-normalised, single line),
`channel_id:str`, `frame_type:str`, `data_quality_id:str`,
`calibration_source_id:str`, `source_product_id:str`, `spice_kernels:str`
(SPICE_FILE_NAME entries joined with `;`).
Image: `lines:int32`, `samples:int32`, `sample_type:str`,
`sample_bits:int16`, `unit:str`.
Spacecraft geometry (float64, degrees/km as in the label): `sub_sc_lat`,
`sub_sc_lon`, `sub_sc_azimuth`, `sc_altitude_km`,
`target_center_distance_km`, `sub_solar_lat`, `sub_solar_lon`,
`sub_solar_azimuth`, `sc_sun_distance_km`, `sc_target_pos_x_km`,
`sc_target_pos_y_km`, `sc_target_pos_z_km`, `sc_target_vel_x_kms`,
`sc_target_vel_y_kms`, `sc_target_vel_z_kms`, `ra_deg`, `dec_deg`,
`twist_deg`, `celestial_north_clock_angle_deg`, `q_w`, `q_x`, `q_y`, `q_z`,
`target_name:str`, `target_pixels:int64`, `target_presence_flag:str`.
Band-group geometry (float64, NaN where the label says `"N/A"`), taken
from the group named by `geom_band`: `incidence_angle`, `emission_angle`,
`phase_angle`, `slant_distance_km`, `min_lat`, `center_lat`, `max_lat`,
`westernmost_lon`, `center_lon`, `easternmost_lon`, `h_pixel_scale_m`,
`v_pixel_scale_m`, `north_azimuth`, `line_first_pixel`,
`sample_first_pixel`.
Sequence columns (computed over the whole table after parsing):
`seq_id:str`, `seq_index:int32`, `seq_n:int32`, `seq_gap_s:float64`.

Decisions:
- `band`: `M` if INSTRUMENT_MODE_DESC contains `M-Band` and not `L-Band`;
  `L` if it contains `L-Band` and not `M-Band`; `LM` if it contains both
  or if `lines == 256`; otherwise `none`.
- `geom_band`: `M` if the M_BAND_PARAMETERS group has a numeric
  CENTER_LATITUDE, else `L` if the L group does, else `none` (band-group
  geometry columns NaN).
- Units in `<…>` are dropped; only the numeric value is stored. `"N/A"`
  -> NaN for numeric columns and null for string columns.
- Longitudes are stored exactly as labelled (0-360, east-positive
  planetocentric; do not convert).
- Sequence segmentation: sort rows by (`orbit_dir`, `band`, `start_time`,
  `product_id`); walking each (`orbit_dir`, `band`) group in time order,
  a new sequence starts at the first row, and whenever the gap from the
  previous row's `start_time` exceeds 45.0 s, or `sequence_number` is
  less than or equal to the previous row's `sequence_number`, or
  `sequence_number` is null. `seq_id` = `f"{orbit_dir:02d}_{band}_{t}"`
  where `t` is the first row's `start_time` formatted `%Y%jT%H%M%S`.
  `seq_index` is the 0-based position, `seq_n` the row count of the
  sequence, `seq_gap_s` the gap to the previous row in the sequence (NaN
  for the first). Rows with `parse_ok=False` get `seq_id=""`,
  `seq_index=-1`, `seq_n=0`, `seq_gap_s=NaN`.
- Parquet written with pyarrow, `index=False`, sorted by (`orbit_dir`,
  `start_time`, `product_id`).
- Public loader: `jiram_catalog.index.load_frames(mirror: str | Path | None = None, orbits: Iterable[int] | None = None) -> pandas.DataFrame`.
- Logging: standard `logging` to stderr at INFO; `-v` sets DEBUG.
- All CLI errors exit non-zero with a one-line message; no tracebacks
  for expected failures (missing manifest, bad `--orbits`).
