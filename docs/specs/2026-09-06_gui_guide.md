Working directory: /expanse/lustre/projects/cla119/kaushiks/jiram_catalog.
Audience: collaborators opening the repository page on GitHub for the
first time, and the owner, who has the app running and finds "a lot
happening". The guide is read in the browser on GitHub, so it is
Markdown with relative image links; no HTML needed.

3. `README.md` rewritten to be GUI-first: title and one-paragraph

   `docs/usage.md`, `docs/gui_guide.md`, `PEDAGOGICAL_REVIEW.md` (may

   Keep the existing README's verified facts where they fit; drop

## How to take screenshots
Headless Chromium via Playwright works on this node:
`uv run --with playwright python <script>` (the browser is already
installed under ~/.cache/ms-playwright). Start the server yourself in a
subprocess: `uv run jiram-catalog gui --port <free port> --no-browser`
with the default mirror; wait until `GET /` returns 200; then use
`page.goto`, `page.wait_for_timeout(…)` generously (Bokeh renders after
load), click tabs by their visible text, set widgets by their labels
where Playwright can find them (Panel widgets render as Bokeh
inputs; use `page.get_by_label`, `get_by_text`, or CSS selectors on the
rendered DOM; inspect `page.content()` when unsure), and
`page.screenshot(path=…, full_page=False)` with a 1400x900 viewport.
Keep the script at `docs/gui_guide/take_screenshots.py` so the images
can be regenerated. Stop the server at the end. Where an interaction
cannot be driven headlessly, say so in the guide and describe it in
words instead of faking an image.

ignore them. No executor product names anywhere. Every claim about a
control must come from the code in `src/jiram_catalog/gui/` (read it).
